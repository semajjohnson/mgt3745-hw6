# DDR-001: bolt.new builds F2, Create a trip and invite members

**Date:** 2026-10-20

## Task

Build feature F2 from `context/FEATURES.md` — create a trip and invite members — satisfying rows F2-1, F2-2 and F2-3, as a working web page in HTML, CSS and JavaScript with no framework and no dependencies. The input was `prompts/PROMPT.md`: a one-line instruction, the three EARS rows, Profile 1 from USERS.md, and the eight style tokens with three refusals. One prompt, no follow-ups. Output committed unmodified at `builds/bolt.zip`.

## Tool and model

bolt.new (StackBlitz), 2026-10-20. Model: bolt.new's standard model; the interface did not name a specific version, and I record that rather than guessing one. Build time 8 minutes, unattended. Project name: Tripcast.

**Retry:** none. One prompt, one run.

## Economic rationale

This delegation was not made to save time. Both builder runs are the subject of the assignment, so the comparison is the deliverable and the build is evidence rather than product.

Measured anyway, the net is sharply negative. The two builds took 13 minutes between them. Evaluating both and writing up the comparison came to about 6 hours: reading bolt's 16 files, running it, confirming the dashboard failure in the browser console, transcribing its invite-code generator for the shared eval, auditing its dependencies and stylesheet, and the same again for AI Studio. Building F2 by hand, against my HW4 pace of about 5 hours for a Worker plus page wiring, would plausibly have been 4 to 6 hours and would have produced something I could run.

The 6 hours is the combined figure for both builder runs and is not counted twice across DDR-001 and DDR-002.

The honest summary is that 8 minutes of generation created several hours of evaluation, and the evaluation is where the value was. A delegation whose output cannot be run costs more to review than one that works, because every verdict has to come from reading source rather than from using the thing.

## Trust Boundary

**Outbound.** `prompts/PROMPT.md` crossed to StackBlitz: three EARS rows, one user profile drawn from a teammate's interview research, and eight style tokens. No credentials, no real personal data, no team repository access. I am accountable for what I pasted.

**Reverse crossing, and the significant finding of this record.** bolt returned more than code.

- A `.env` file holding a live `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, in a project whose own `.gitignore` does not list `.env`. Committing the zip put a credential in a public repository.
- A Supabase dependency and a live Supabase project. Signing in to test the build created a real account on a vendor that appears nowhere in TOOLS.md and is contrary to ADR-001, which names Cloudflare Workers and D1. The account holds my email address.
- `index.html` carrying `og:image` and `twitter:image` pointing at `bolt.new`.

None of this was asked for. The prompt said no dependencies and named no backend; F2-1's phrase "a signed-in person" was enough for bolt to choose a vendor, provision a database, and hand back the key.

## Findings

**Passed 1 of 3 EARS rows.** F2-2 passes: an invalid code is refused with no trip details shown, and the 32-character random invite code discloses nothing about the trip, confirmed by the shared code eval.

**Failed F2-1.** Not degraded, unreachable. `create_trip()` is written correctly but no create form can be reached, because the dashboard returns 500s consistent with the `trip_members` access policy querying `trip_members` while the `trips` policy queries it too. The display name collected at sign-up is also never stored: `views/trip-detail-view.js:162` renders `Member ${userId.slice(0, 8)}`.

**Partial on F2-3.** The invite code is unique and reusable by design, but unusable: `views/join-view.js` destructures `{ data: session }` from `getSession()` then checks `session.data?.session`, which is always undefined, so even signed-in users are bounced.

**Its own summary was wrong.** bolt reported that nothing loads from another origin, while the app calls Supabase on every action and its `index.html` references bolt.new image URLs. A builder that misreports compliance makes everything else it says unusable without checking.

**What I could not fully verify.** I identified the recursion in the access policies by reading the two migration files, but the browser only showed me 500 responses. I never saw the database's own error text, because I could not reach the Network tab's response body before running out of time. The causal claim in my comparison is a code reading supported by consistent symptoms, not a message the server gave me. The next step is `npx supabase db reset` locally, or reading the response body in DevTools, either of which would settle it in ten minutes.

**What I did about the credential.** Removed the `.env` from the packet sent to the second grader, so the key did not cross to a third vendor. _(Record what you did about the committed zip and the Supabase key itself.)_
