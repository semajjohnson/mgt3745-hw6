## Economic rationale

As with DDR-001, the run is the subject of the assignment rather than a labor-saving choice, and the net is negative: 5 minutes 7 seconds of generation against about 6 hours of evaluation and write-up across both builds. That 6 hours is the combined figure stated in DDR-001 and is not counted twice.

The difference from bolt is worth recording, because it is the one place this delegation genuinely saved time. AI Studio's build runs. I could evaluate it by using it — signing in as a non-member, opening a trip, watching what appeared — rather than by reading source and inferring. The F2-2 failure took about two minutes to find by clicking, and would have taken far longer to find by reading. A delegated build that runs is cheaper to review than one that does not, by a margin large enough to be a criterion in my recommendation.

**Outbound.** The same `prompts/PROMPT.md` crossed to Google: three EARS rows, one user profile drawn from a teammate's interview research, eight style tokens. No credentials, no real personal data, no repository access. I am accountable for what I pasted. **Reverse crossing.** AI Studio returned a `package.json` declaring nineteen packages across dependencies and devDependencies — React, React DOM, Tailwind, express, `lucide-react`, `motion`, `@google/genai`, and more — none of which its own `src/main.ts` imports. ## Findings

**Passed 2 of 3 EARS rows.** F2-1 and F2-3 both work: a trip is created with its creator attached and a reusable invite link, and the link works for joining.

**Failed F2-2, twice over, and this is the finding that decided my recommendation against taking its output as-is.** Signed in as Elena, a non-member who used no invite link at all, the trip page showed the trip name, creator, note, member count and the invite link itself. "All Trips" lists trips marked "Not a member" with a button to open each. Only the moments section checks membership. Separately, the invite code is built from the slugified trip name plus six random characters (`src/main.ts:184-186`), producing links like `weekend-in-lisbon-k9x2qd`, so the link discloses the trip even where a refusal works correctly. The shared code eval fails on this and passes on bolt's generator.

**Faked the dependency the spec did not define.** F2-1 says "a signed-in person"; AI Studio built a dropdown that switches between invented people, with all state in `localStorage`. F2-3's "reusable" link therefore cannot be exercised across devices, which makes a Must-be row untestable rather than failed.

**Its own summary was wrong.** It reported that it has no external dependencies and that trip details are never shown without a valid link. Both are checkably false, the second one being the row it failed.

**Style was the strongest part.** All eight tokens used correctly, every font size defined as a token with none below the 14px minimum, nothing loaded from another origin. It invented five colors the tokens do not define — two message backgrounds, two borders, a hover shade — because the prompt names no tint or hover state. That is a gap in my style rules rather than disobedience, and it is spec gap 6 in COMPARISON.md.

**What I could not fully verify.** Whether its filtering and matching behave correctly for invite tokens containing non-ASCII characters. My tests use plain ASCII and the trip-name slugifier strips everything outside `a-z0-9`, so a trip named in another script would produce the fallback token `trip-` plus six characters, and I did not test whether two such trips collide. Recorded rather than assumed; a test with a non-ASCII trip name would settle it.
