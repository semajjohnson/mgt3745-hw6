# DDR-003: Gemini as second grader for the judgment eval

**Date:** 2026-10-20

## Task

Answer the 24 binary questions in `docs/JUDGMENT.md` — twelve per build — against both builders' source and screenshots, with one sentence of evidence per answer naming a file, a line, or a screenshot. Produce a second independent column so the judgment eval has an agreement rate rather than one person's opinion.

## Tool and model

Gemini 3.8, 2026-10-20. Run in a session with no history of this project. The same model family built the AI Studio project in DDR-002, which is a weakness in this eval and is named in the findings below.

**Retry:** one follow-up, recorded. The first return gave 24 verdicts with no evidence at all, despite the packet requiring a citation per answer. I asked for the evidence column without changing any verdict, and told it to write "no specific evidence" rather than reconstruct a reason where it had none. It returned evidence for all 24 and used that exit on none of them.

## Economic rationale

A classmate would have been the better grader and was not available in the time left. The run took about 15 minutes including assembling the packet; a classmate would have taken a day of waiting. The audit afterward took roughly 45 minutes, three times the grading, which is the real cost and the real lesson: a model grader is cheap to run and expensive to trust.

## Trust Boundary

**Outbound.** `grader-packet.zip` crossed to Google: the prompt both builders received, the team's full `context/FEATURES.md`, both builds' complete source, and five screenshots of the running applications. This is the third vendor to receive my team's specification in one afternoon.

I deliberately removed bolt's `.env` from the packet before sending it, so the live Supabase credentials did not cross to a third party. The packet's own README states that the file was removed and why, so its absence would not be read as the builder never producing one.

Also deliberately excluded: my answers, `COMPARISON.md`, `EVALS.md`, the `evals/` folder, and any analysis of mine. The assignment requires the second grader to see the same evidence with no summary from me.

**Reverse crossing.** Text only. Nothing from this run is committed as code.

## Verification performed

I audited every one of the grader's 24 citations against the packet I actually sent.

## Findings

**Agreement: 24 of 24, 100%.** Every verdict matched my column.

**The agreement does not survive the audit, and that is the finding.**

- **J8 cites `evals/invite-code.test.mjs`, which was not in the packet.** The packet held the prompt, the specification, both builds' source and five screenshots. The grader named a test file it could not have opened.
- **J18 cites `aistudio-f2-2-nonmember-sees-trip.png` as showing "successful membership expansion via active invite tokens."** That screenshot shows a non-member reaching a trip without using any link, which is the opposite of joining through one.
- **J17's evidence contradicts its own verdict.** It answers Yes, that a non-member can reach a trip page without a link, then explains that access is "governed by valid invite routing."
- **J9 states that bolt's `package.json` "includes multiple production dependencies."** It declares one, plus Vite as a dev dependency. The nineteen-package build is AI Studio's.
- **Every file path is wrong by one segment** (`builds/bolt/` where the packet's folder is `build-bolt/`), suggesting reconstruction rather than quotation.

Two citations are exact and correct: J3's `trip-detail-view.js:162` and J20's `src/main.ts:184-186`. Both match what I found independently, so the grader did read some of the source.

**What I could not verify, and what I did about it.** I cannot tell which of the 24 verdicts were reached by reading and which were produced to agree with a plausible reading of the question. The two correct citations prove it read something; the four bad ones prove it did not read everything. There is no way to separate those from one run. Rather than discard the result or accept it, I kept the 100% and published the audit beside it in `docs/JUDGMENT.md`, with the failure logged in the `EVALS.md` error log. Agreement from a grader whose reasoning fails inspection is not independent confirmation, and saying so is more useful than a clean number nobody can check.

**A structural weakness I should have caught before running it.** Gemini 3.8 graded a build that Gemini 3.8 produced. The assignment's own caution is that an assistant which helped build something should not be its only grader, and I applied that rule to Claude, which helped me analyze the builds, while missing that it applied to Gemini and the AI Studio build just as directly. Twelve of the 24 items asked a model to judge its own family's output. I have no way to measure what that did to the result, and the fix was available: ask a classmate, or use a third vendor for the AI Studio half.

**What I would change.** Use a grader from neither builder's family. Require the evidence in the same response as the verdict, since a citation produced afterward is written to defend a position already taken. State in the packet which files are and are not included, so a citation to an absent file is detectable rather than merely suspicious. And include at least one question whose answer cannot be reached by pattern-matching a filename.
